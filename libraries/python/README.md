# semantic-versions

The Python implementation of [**Semantic Versions**](https://semver.xyz): parse,
validate, compare and range-match version numbers, with builds that participate
in precedence.

It is a port of the JavaScript reference implementation
([`semantic-versions`](https://www.npmjs.com/package/semantic-versions) on npm)
and behaves identically: both pass the same
[conformance suite](https://github.com/vltpkg/semantic-versions/tree/main/conformance),
and they agree on every version, range and resolution in the benchmark corpus.
Pure Python 3.10+, typed, no dependencies.

## Install

```sh
pip install semantic-versions
```

## Usage

```python
import semantic_versions as sv

v = sv.parse("1.2.3-beta.4+build.7")
assert (v.major, v.minor, v.patch, v.pre, v.build) == (1, 2, 3, "beta.4", "build.7")

# Builds participate in precedence: a build ranks above its plain release.
assert sv.parse("1.0.0") < sv.parse("1.0.0+build.1")

assert sv.satisfies("1.4.0", "^1.2.3")
assert sv.satisfies("1.0.0-rc.1", "^1.0.0-rc")      # pre-release channel
assert not sv.satisfies("1.0.0-beta", "^1.0.0-rc")  # a different channel
assert sv.satisfies("1.4.2+win.x64", "^1.0.0+win")  # build channel
assert sv.valid_range("~>1.2") == ">=1.2.0 <2.0.0-0"

# Contexts scope a version or range to an identity.
react = sv.Range("npm:react@^18")
assert sv.parse("npm:react@18.2.0") in react
assert sv.parse("pypi:react@18.2.0") not in react

assert sv.max_satisfying(["1.0.0", "1.9.0", "2.0.0"], "^1") == "1.9.0"
assert sv.sort(["2.0.0", "1.0.0+b", "1.0.0"]) == ["1.0.0", "1.0.0+b", "2.0.0"]
assert sv.valid("v1.2.3") is None  # no coercion
```

`parse` raises `InvalidVersion` and `Range()` raises `InvalidRange` (both
`ValueError`s); `valid`, `valid_range`, `satisfies` and friends return `None` or
`False` instead.

## How this differs from `node-semver` and `semver`

- **Builds participate in precedence** (`1.0.0 < 1.0.0+build`), and a build on a
  comparator is a [channel filter](https://semver.xyz/spec/#build-channels).
- **Pre-releases are range-driven**: a pre-release on a comparator is a
  [prefix channel](https://semver.xyz/spec/#pre-release-channels) scoped to its
  tuple; `X.Y.Z-*` and `*-*` opt in explicitly.
- **Contexts**: `npm:react@18.2.0`, `npm:@babel/core@^7`.
- **No coercion**: `v1.2.3` and `1.2` are errors.
- **npm-style ranges** (`>=1.2.0 <2.0.0`, `||`, `1.x`, `~`, `^`, `~>`, hyphen ranges), which python-semver does not have.
