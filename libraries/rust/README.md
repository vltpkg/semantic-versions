# semantic-versions

The Rust reference implementation of [**Semantic Versions**](https://semver.xyz):
parse, validate, compare and range-match version numbers, with builds that
participate in precedence.

[![crates.io](https://img.shields.io/crates/v/semantic-versions.svg)](https://crates.io/crates/semantic-versions)
[![docs.rs](https://img.shields.io/docsrs/semantic-versions)](https://docs.rs/semantic-versions)
[![spec](https://img.shields.io/badge/spec-semver.xyz-111.svg)](https://semver.xyz)

It implements the [specification](https://semver.xyz/spec/) and its
[BNF grammars](https://semver.xyz/grammar/), and behaves identically to the
JavaScript reference parser ([`semantic-versions`](https://www.npmjs.com/package/semantic-versions)
on npm): both pass the same [conformance suite](https://github.com/vltpkg/semantic-versions/tree/main/conformance),
and they agree on every version, range and resolution in the benchmark corpus.
No dependencies and no `unsafe`.

## Install

```sh
cargo add semantic-versions
```

## Usage

```rust
use semantic_versions::{max_satisfying, satisfies, valid_range, Range, Version};

let v: Version = "1.2.3-beta.4+build.7".parse().unwrap();
assert_eq!((v.major, v.minor, v.patch), (1, 2, 3));

// Builds participate in precedence: a build ranks above its plain release.
assert!(Version::parse("1.0.0").unwrap() < Version::parse("1.0.0+build.1").unwrap());

assert!(satisfies("1.4.0", "^1.2.3"));
assert!(satisfies("1.0.0-rc.1", "^1.0.0-rc"));   // pre-release channel
assert!(!satisfies("1.0.0-beta", "^1.0.0-rc"));  // a different channel
assert!(satisfies("1.4.2+win.x64", "^1.0.0+win")); // build channel
assert_eq!(valid_range("~>1.2").as_deref(), Some(">=1.2.0 <2.0.0-0"));

// Contexts scope a version or range to an identity.
let range = Range::parse("npm:react@^18").unwrap();
assert!(range.test(&"npm:react@18.2.0".parse().unwrap()));
assert!(!range.test(&"cargo:react@18.2.0".parse().unwrap()));

assert_eq!(max_satisfying(["1.0.0", "1.9.0", "2.0.0"], "^1"), Some("1.9.0"));
```

## How this differs from `semver` and `nodejs-semver`

- **Builds participate in precedence** (`1.0.0 < 1.0.0+build`), and a build on a
  comparator is a [channel filter](https://semver.xyz/spec/#build-channels).
- **Pre-releases are range-driven**: a pre-release on a comparator is a
  [prefix channel](https://semver.xyz/spec/#pre-release-channels) scoped to its
  tuple; `X.Y.Z-*` and `*-*` opt in explicitly.
- **npm-style range syntax** (`>=1.2.0 <2.0.0`, `||`, `1.x`, `~`, `^`, `~>`,
  hyphen ranges) rather than Cargo's comma-separated requirements, where a bare
  `1.2.3` means `^1.2.3`. Here a bare version means exactly that version.
- **Contexts**: `npm:react@18.2.0`, `npm:@babel/core@^7`.
- **No coercion**: `v1.2.3` and `1.2` are errors.

## Performance and conformance

[`nodejs-semver`](https://crates.io/crates/nodejs-semver) on real versions and
dependency ranges from the npm registry. Method and raw results:
[`benchmarks/`](https://github.com/vltpkg/semantic-versions/tree/main/benchmarks).
