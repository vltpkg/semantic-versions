# semantic-versions for Java

The Java implementation of [**Semantic Versions**](https://semver.xyz): parse,
validate, compare and range-match version numbers, with builds that participate
in precedence.

It is a port of the JavaScript reference implementation
([`semantic-versions`](https://www.npmjs.com/package/semantic-versions) on npm)
and behaves identically: both pass the same
[conformance suite](https://github.com/vltpkg/semantic-versions/tree/main/conformance),
and they agree on every version, range and resolution in the benchmark corpus.
Java 17+, no dependencies; usable from Kotlin, Scala and any other JVM language.

## Install

```xml
<dependency>
  <groupId>xyz.semver</groupId>
  <artifactId>semantic-versions</artifactId>
  <version>1.0.0</version>
</dependency>
```

Gradle: `implementation("xyz.semver:semantic-versions:1.0.0")`

## Usage

```java
import xyz.semver.Range;
import xyz.semver.SemanticVersions;
import xyz.semver.Version;
import java.util.List;

Version v = Version.parse("1.2.3-beta.4+build.7");
v.major();      // 1
v.prerelease(); // "beta.4"
v.build();      // "build.7"

// Builds participate in precedence: a build ranks above its plain release.
Version.parse("1.0.0").compareTo(Version.parse("1.0.0+build.1")); // -1

SemanticVersions.satisfies("1.4.0", "^1.2.3");             // true
SemanticVersions.satisfies("1.0.0-rc.1", "^1.0.0-rc");     // true: pre-release channel
SemanticVersions.satisfies("1.0.0-beta", "^1.0.0-rc");     // false: a different channel
SemanticVersions.satisfies("1.4.2+win.x64", "^1.0.0+win"); // true: build channel
SemanticVersions.validRange("~>1.2");                      // ">=1.2.0 <1.3.0-0"

// Contexts scope a version or range to an identity.
Range react = Range.parse("npm:react@^18");
react.test(Version.parse("npm:react@18.2.0"));   // true
react.test(Version.parse("maven:react@18.2.0")); // false

SemanticVersions.maxSatisfying(List.of("1.0.0", "1.9.0", "2.0.0"), "^1"); // "1.9.0"
```

`Version.parse` and `Range.parse` throw `SemanticVersionException` (an
`IllegalArgumentException`); `tryParse` returns `null` instead.

## How this differs from `semver4j` and `java-semver`

- **Builds participate in precedence** (`1.0.0 < 1.0.0+build`), and a build on a
  comparator is a [channel filter](https://semver.xyz/spec/#build-channels).
- **Pre-releases are range-driven**: a pre-release on a comparator is a
  [prefix channel](https://semver.xyz/spec/#pre-release-channels) scoped to its
  tuple; `X.Y.Z-*` and `*-*` opt in explicitly.
- **Contexts**: `npm:react@18.2.0`, `npm:@babel/core@^7`.
- **No coercion**: `v1.2.3` and `1.2` are errors.

## Develop

The library and its tests have no dependencies, so the JDK is all you need:

```sh
javac -d build $(find src -name '*.java')
java -cp build xyz.semver.ConformanceTest   # conformance suite
bench/run.sh                                # benchmarks
mvn package                                 # the jar, sources and javadoc
```

Releases go to Maven Central under the `xyz.semver` namespace with
`mvn -P release deploy`, which GPG-signs the artifacts and uploads them with the
Central Portal token in `~/.m2/settings.xml` (server id `central`).
